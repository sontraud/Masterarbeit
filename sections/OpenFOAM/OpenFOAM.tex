\section{Introduction to OpenFOAM}
\texttt{OpenFOAM}, short for Open Source Field Operation and Manipulation, is a \lstinline|C++| based toolbox for continuum mechanics problems, including computational fluid dynamics. Here we use \lstinline|v2412| which is available on the \footnote{\url{https://www.openfoam.com/}} website.
Provided in \OF are pre-processing tools, e.g. for meshing, solvers, e.g. the \lstinline|MPPICFoam| and post-processing tools which we will use later in the results chapter. Apart from \OF we use \lstinline|Paraview| \footnote{\url{https://www.paraview.org/}} for visualization and \lstinline|miniconda3| \footnote{\url{https://www.anaconda.com/docs/getting-started/miniconda/main}} scripts for evaluation of data.

In the \lstinline|0| directory we define the initial conditions and boundary conditions, in this case for the fluid velocity and the kinematic pressure.

In the \lstinline|system| directory we set the parameters for solving. In \lstinline|controlDict| run parameters are defined including the time step, start and end times as well as post-processing procedures. In \lstinline|fvSchemes| we set the discretization schemes used and in \lstinline|fvSolution| we specify the solvers and their respective tolerances. In \lstinline|blockMeshDict| we set up our geometry.

In the \lstinline|constant| directory we specify physical properties. Contained in the subdirectory \lstinline|polyMesh| is the information about the mesh for our simulation. In \lstinline|kinematicCloudProperties| we define the properties of the Lagrangian phase including the models and constants used for the injection of the particles, the particle normal stress model and the damping terms.

In the time directories, not shown in the figure, the data of the specified fields in output during the simulation. In our case these are among other outputs the fluid velocity, fluid volume fraction, pressure and the \lstinline|lagrangian| folder which includes output about the velocity and position of the particles.

\section{\MP method in OpenFOAM}
Although the \MP method was presented in the mid 90s \cite{MPPICFirst} and extended to a three dimensional method in 2001 \cite{MPInterpolation}, it was implemented in \OF in 2014 \cite{OFMPIntro}.
The solver in \OF is called \lstinline|MPPICFoam| and can be executed by running the likewise named command.
The solver is part of the \lstinline|DPMFoam| family. \lstinline|DPMFoam| uses the same equations for the Eulerian phase but resolves particle collisions. \lstinline|MPPICFoam| is located under the same directory: \lstinline|applications/solvers/lagrangian/| \lstinline|DPMFoam/MPPICFoam|. 
The \MP method is an incompressible transient solver that calls upon the \lstinline|Lagrangian| framework to solve for the particle trajectories. 
For the Eulerian phase, we recall the governing equations from the previous chapter: mass conservation and momentum conservation
\begin{align*}
    \dfrac{\partial (\fvf \rf)}{\partial \tvar} + \nabla \cdot (\fvf \rf \uf) &= 0, \\
    \dfrac{\partial (\fvf \rf \uf)}{\partial \tvar} + \nabla \cdot (\fvf \rf \uf \uf) &= - \nabla \p -\nabla \cdot (\fvf \fst)  - \F + \fvf \rf \g .
\end{align*}

For the discrete phase we previously looked at the particle continuity equation and at the particle momentum equation.
These are not solved directly in the \MP implementation in \OF since the Lagragian class is explicitly tracking particles.
Both of these terms are necessary to see where the  kinematic stress and the interphase momentum transport arise. For both of these models are implemented in \OF that account for their contribution to the particle velocity.

In \OF the two phases are split into the Lagragian loop (evolve kinematic cloud) and the Eulerian loop (\texttt{PIMPLE}). The steps in-between connect the two phases.
In the following we will go into detail for each step.
The implementation of the \MP method in \OF is partially explained in \cite{reportMPPIC}, \cite{chimera} and \cite{ImplemInter}. The former focuses more on the current \MP implementation, while the latter two extend the current implementation to include a chimera mesh or respectively coarse particles.

\subsection{Create Fields}
In the file \lstinline|createFields.H| the fields used later are defined and initialized. 
In the \MP method we first initialize the Eulerian fields, therefor the velocity, kinematic pressure, face flux, turbulence, density and kinematic viscosity, and the fluid volume fraction, which is initialized as zero and calculated at the end of \lstinline|createFields.H|.
Afterward, the particles are inserted as a kinematic cloud. The upper limit of the particle volume fraction is calculated by using the user defined maximum packing, which can be set in \lstinline|kinematicCloudProperties|.
The fluid volume fraction is calculated by interpolating the particle positions to the Eulerian grid.
Finally, the turbulence model is initialized.


\subsection{Continuous Phase Transport}
We start by updating the fluid transport properties, e.g. the kinematic viscosity.
The dynamic viscosity is then calculated by multiplying the kinematic viscosity with the density.
These are needed to update the particle positions.

\subsection{Evolve Kinematic Cloud}
Evolving the kinematic cloud is done by calling \lstinline|kinematicCloud.evolve();| in the \lstinline|MPPICFoam.C| file. This calls the \lstinline|solve| method from the Lagrangian kinematic cloud class.
It can be split into roughly four steps. First the kinematic cloud is prepared in the \lstinline|preEvolve| step and relevant data is cached. Then the particles are moved in \lstinline|evolveCloud|. 
If the solver is coupled the new velocity is offset with the old velocity, which is done in \lstinline|coupled|.
Lastly, in \lstinline|postEvolve| cached data is released and relevant data is written out.
This represents the standard Lagragian kinematic cloud evolving.
The \MP method is worked into the \lstinline|evolveCloud| method, more specifically into \lstinline|motion|.
In the following flow chart \ref{fig:FCEvoleCloud} we outline which methods are called when the kinematic cloud is evolved.
We will look at each step in more detail in the following.

\subsubsection{preEvolve}
The \lstinline|preEvolve| prepares for the movement of the particles by caching important properties.
First, the mesh validity is checked.
Next Eulerian fields are cached for efficient memory usage and properties from the Eulerian mesh are later used to update particle positions.
The damping and packing models are prepared. The properties required for the models are cached.
\ifcode
\begin{lstlisting}[firstline = 782, caption=in KinematicCloud.C]
    template<cklass CloudType>
void Foam::KinematicCloud<CloudType>::preEvolve
(
    const typename parcelType::trackingData& td
)
{
    // force calculation of mesh dimensions - needed for parallel runs
    // with topology change due to lazy evaluation of valid mesh dimensions
    label nGeometricD = mesh_.nGeometricD();

    Log_<< "\nSolving" << nGeometricD << "-D cloud " << this->name() << endl;

    this->dispersion().cacheFields(true);
    forces_.cacheFields(true);

    pAmbient_ = constProps_.dict().template
        getOrDefault<scalar>("pAmbient", pAmbient_);

    if (this->dampingModel().active() || this->packingModel().active())
    {
         const_cast<typename parcelType::trackingData&>(td).updateAverages(*this);
    }

    if (this->dampingModel().active())
    {
        this->dampingModel().cacheFields(true);
    }
    if (this->packingModel().active())
    {
        this->packingModel().cacheFields(true);
    }

    updateCellOccupancy();

    functions_.preEvolve(td);
}

\end{lstlisting}
\fi

\subsubsection{evolveCloud}
The method \lstinline|evolveCloud()| is what moves the particles along their trajectories. 
% In the Lagrangian loop the we split the time step into sub time steps which is limited by the maximal Courant number. 
% First \lstinline|canEvolve()| is called, which checks if we have reached the next time step.
%For details the code is included in the following listing \ref{code:evolveCloud}.
First the source terms are reset. The source terms that contribute to the continuous equations will be built after the kinematic cloud has evolved.
For a transient solver, like the \MP method the particles are injected in two steps.
To check whether injection of particles has taken place, the current cloud size is recorded.
First particles generated from films, e.g walls, are injected.
If necessary, cell occupancy is updated.
In the second step, particles are injected from inlets.
Properties such as the velocity, size of the particles which is either pre-defined or given via a distribution etc. are set in this step from the tracking data \lstinline|td|.
The \lstinline|cloud.motion| command then moves the particles to their new time steps.
The motion method is defined in the \lstinline|MPPICCloud.C| file. This differs from the standard motion of the kinematic cloud. It will be discussed in the next section.
The stochastic collision model which is executed at the end of the evolve function is turned off in the \MP model, because a similar term is included in the return-to-isotropy damping model that is executed in \lstinline|motion|.

\ifcode
\begin{lstlisting}[firstnumber=221,caption=from kinematicCloud.C, label ={code:evolveCloud}]
    template<class CloudType>
template<class TrackCloudType>
void Foam::KinematicCloud<CloudType>::evolveCloud
(
    TrackCloudType& cloud,
    typename parcelType::trackingData& td
)
{
    if (solution_.coupled())
    {
        cloud.resetSourceTerms();
    }

    if (solution_.transient())
    {
        label preInjectionSize = this->size();

        this->surfaceFilm().inject(cloud);

        // Update the cellOccupancy if the size of the cloud has changed
        // during the injection.
        if (preInjectionSize != this->size())
        {
            updateCellOccupancy();
            preInjectionSize = this->size();
        }

        injectors_.inject(cloud, td);

        // Assume that motion will update the cellOccupancy as necessary
        // before it is required.
        cloud.motion(cloud, td);

        stochasticCollision().update(td, solution_.trackTime());
    }
    else
    {
//        this->surfaceFilm().injectSteadyState(cloud);

        injectors_.injectSteadyState(cloud, td, solution_.trackTime());

        td.part() = parcelType::trackingData::tpLinearTrack;
        CloudType::move(cloud, td, solution_.trackTime());
    }
}

\end{lstlisting}
\fi

In this section we are going to exclude the collision damping model described in \ref{sec:DiscCollDamp} because as stated in \cite{chimera} including this model in \OF currently causes errors.
Because the results discussed in Sec. \ref{sec:DampResults} also do not show promising results we do not discuss the implementation here.



In the previous section we defined the advanced time velocity in equation \eqref{eq:errVel} as
\begin{equation*}
    \up^{n+1} = \dfrac{\up^n + \Delta \tvar \left[ \d \up^{n+1} - \dfrac{1}{\rp} \nabla \p_p^{n+1} - \dfrac{1}{\rp \pvf} \nabla \scs^{n+1} - \g \right]}{1 + \Delta \tvar \d} .
\end{equation*}


Several drag terms are implemented in \OF which includes the Plessis-Masliyah drag model \cite{Plessis}
\begin{equation*}
    \d = (A \pvf + B \operatorname{Re}_p) \dfrac{\pvf \mu_f}{\fvf^2 d^2} \qquad \operatorname{Re}_p = \dfrac{\rf \lvert \u_{rel} \rvert d}{\mu_f}
\end{equation*}
with coefficients $A$ and $B$ chosen as
\begin{equation*}
    A = \dfrac{26.8 \fvf^2}{\pvf^{2/3}(1-\pvf^{1/3})(1-\fvf^{2/3})} \qquad B = \dfrac{\fvf^2}{(1-\pvf^{2/3})^2}
\end{equation*}
and the Ergun-Wen-Yu model \cite{ErgunWenYu}
\begin{align*}
    \d &= \begin{cases}
        \dfrac{3 (1-\fvf) \mu_f \fvf \operatorname{Re}_p}{d_p^2} C_D \fvf^{-2.65} & \text{if } \fvf \geq 0.8 \\
        \left(150 \dfrac{1-\fvf}{\fvf} + 1.75 \operatorname{Re}_p \right) \dfrac{(1-\fvf) \mu_f}{d_p^2} & \text{if } \fvf < 0.8
    \end{cases}
\end{align*}
with
\begin{align*}
    C_D &= \begin{cases}
        24 \left(1+0.15 \operatorname{Re}_p^{0.687}\right) & \text{if } \operatorname{Re}_p < 1000 \\
        0.44 & \text{if } \operatorname{Re}_p \geq 1000
    \end{cases}
\end{align*}
which uses the Ergun expression for fluid volume fractions below $0.8$ .
Other drag models like the Wen-Yu model only give a good approximation up to a particle volume fraction of $0.2$ and therefor not considered here.

For the velocity update small changes in the particle solid stress can have a big influence the particle normal stress the velocity is updated in a first step without the particle normal stress. 
With the new particle positions the particle normal stress is applied.
The terms are split as follows
\begin{align*}
    \up^{n+1} & = \tilde{\up}^{n+1} + \u_{p,\scs} \\
    \tilde{\up}^{n+1} &= \dfrac{\up^n + \Delta \tvar \left[ \d \up^{n+1} - \dfrac{1}{\rp} \nabla \p_p^{n+1} + \g \left( 1- \dfrac{\rf}{\rp}\right) \right]}{1 + \Delta \tvar \d} \qquad \u_{p,\scs} = - \dfrac{\Delta \tvar \nabla \scs}{\rp \pvf (1+\Delta \tvar \d)}
\end{align*}
with the previously unregarded buoyancy force included in the first term.


In the \OF implementation the drag term is neglected in the denominator of the solid stress velocity due to it being either dominated or insignificant. Instead a small factor is included
%\todo{Überlege noch ob das Sinn ergibt. Bin gerade nicht ganz sicher...}
\begin{equation*}
    \u_{p,\scs} = - \dfrac{\Delta \tvar \nabla \scs}{\rp (\pvf + \operatorname{SMALL})}
\end{equation*}

The gas phase time step is split into several smaller time steps in which particles are moved. At the beginning of \lstinline|move| the time fraction is set to zero.


In the first step only the first term that depends on particle forces is applied to the particles and they are moved accordingly.
The new particle positions are
\begin{equation*}
    \xp^{(lag),n+1} = \xp^{(lag),n} + \tilde{\up}^{lag}.
\end{equation*}
The time step that is chosen here is based on the time step fraction.

Here \lstinline|carrierDt| is the time step given by the continuous phase. 
The new time step fraction is calculated in three steps.
First we calculate the remainder of the step fraction of the continuous phase \lstinline|f| to ensure we do not go beyond the next continuous phase time step.
\begin{lstlisting}[caption = parcels/Templates/KinematicParcel/KinematicParcel.C, label = {code:stepFraction}]

    f = min(f, maxCo);
    f = min(f, maxCo*l/max(SMALL*l, mag(s)));
\end{lstlisting}
To prevent overshooting, we check if \lstinline|f| is larger than the maximal Courant number
and the length scaled Courant number
with the displacement over the total continuous time step and the characteristic length of the cell $l$.
In last step we check the fraction of the maximal allowed particle distance traveled $\operatorname{maxCo} l$ by the total displacement over the time step.
The value \lstinline|f| is then added to the current time fraction.

To explain in which cases the particle normal stress model is applied we simplify the problem. In the following figure \ref{fig:WhenPacking} the particle normal stress model is applied for the cases marked in green.
For the figure we assume that the packed bed is on the left hand side and the particle volume fraction monotone increasing toward the packed bed, therefor the gradient in each part of the figure would increase toward the left side of the figure.
Applying the packing model would accelerate the particle in the opposite direction. 
This is useful in three cases.
In the first case both the particle and the mean field are moving toward the packed bed. The particle moves faster than the mean field. Here the particle is decelerated.
In the second case, depicted on the bottom left, the particle is moving toward the packed bed, but the mean field is moving away. In this case the particle is accelerated away from the packed bed.
In the last case the particle is moving away from the bed at a slower speed than the mean field. In this case the particle accelerated.
In the other three cases accelerating the particle would lead to unphysical behavior.

How the gradient of the particle normal stress \lstinline|tauGrad| is calculated depends on the chosen particle normal stress model.
In \OF two particle normal stress models are implemented.
The here discussed Harris and Crighton model
% \begin{equation*}
%     \scs = \dfrac{P_s \pvf^\beta}{\pvfcp - \pvf}.
% \end{equation*}
as well as the Lun particle normal stress model which were briefly explained in section \ref{sec:particleNormalStress}. 
For numerical stability the denominator is restricted with a small number $\varepsilon$ to prevent divergence.
In the Harris and Crighton model this is 
\begin{equation*}
    \nabla \scs = 
    \dfrac{P_s (\pvfi^n)^\beta}{\max [\pvfcp - \pvfi^n, \max \{\varepsilon (1 - \pvfi^n), \operatorname{SMALL} \}]} 
    \left(\dfrac{\beta}{\pvfi^n} + \dfrac{1}{\max [\pvfcp - \pvfi^n, \max \{\varepsilon (1 - \pvfi^n), \operatorname{SMALL} \}]} \right),
\end{equation*}
with the constant \lstinline|SMALL| that is executed by the \lstinline|C++| library \verb|numeric_limits| and is a system-dependent number that depends on the used floating-point arithmetic.
This further restricts the denominator to prevent numerical instabilities near close pack.

For each particle we preform an accept-reject algorithm by first drawing from a uniform distribution $X_p \sim \mathcal{U}([0,1))$. 
If the drawn value is smaller or equal than $\operatorname{exp}(-\Delta \tvar / \ss_G)$ than no collision has taken place and the velocity of the particle stays the same. The return-to-isotropy damping time is defined in the previous chapter \eqref{eq:DampingTimeG}.
This implies that the probability of collision goes towards $1$ for the damping term approaching zero or in physical terms that when we expect the time until the next collision to be zero that there is a collision, see figure \ref{fig:colNoCol}.
%\Todo{Farben anpassen} \ref{fig:colNoCol}.

If the code determines that a collision has taken place an updated velocity is drawn from a Gaussian distribution centered around the mean velocity $\overline{\up}$ with the velocity variance $\sigma^2$.
% \begin{equation*}
%     G(\up ; \overline{\up}, \sigma^2(\m)) = \left(\dfrac{2}{3} \pi \sigma^2(\m)\right)^{-\frac{3}{2}} \operatorname{exp} [-(\up - \overline{\up})/(2/3\sigma^2(\m)).
% \end{equation*}
%\todo{chi2 Ver\-teilung $\sim$ Exp(1/2), uninteressant?}
We use two uniform standard distributions and transform the via a Box-Muller %\todo[color=kit-blue!60]{Box-Mueller erklären?} 
sampling algorithm to a Gaussian distribution by representing them in polar coordinates
\cite{numericalRecipies}.
\begin{equation*}
    X \sim \mathcal{N}(\mu , \sigma^2) \qquad \Rightarrow \qquad aX+b \sim \mathcal{N} (a \mu + b, a^2 \sigma^2)
\end{equation*}
we can avoid calculating the Gaussian distribution but instead shift the standard normal distribution \cite{Stochastic}.
This yields a different distribution that has the same mean and variance.
The distribution we calculate first is centered around zero with a variance of one. Adding the mean velocity and the velocity variance we thus get our desired distribution.
To account for the three dimensional method in \OF we norm the added velocities by $\sqrt{1/3}$
\begin{equation*}
    \up = \overline{\u} + \dfrac{1}{\sqrt{3}} g \left( \sum_p \Np \mp (\up - \overline{\u})^2\right).
\end{equation*}
This differs from the Gaussian distribution from the paper \eqref{eq:rtiDist} but holds the same mean and variance properties.
The previous velocity of the particle is overwritten.
\ifkeepcode
\begin{lstlisting}
    p.U() = u + r*uRms*oneBySqrtThree;
\end{lstlisting}
\fi
Here \lstinline|uRms| is the variance, \lstinline|u| is the mean particle velocity and \lstinline|oneBySqrtThree| is $\sqrt{1/3}$.
Afterward, velocities are adjusted for momentum conservation.
\ifkeepcode
\begin{lstlisting}
    p.U() = u + (p.U() - uTilde)*uRms/max(uTildeRms, SMALL);
\end{lstlisting}
\fi
This is done as described above in equation \eqref{eq:rtiUpdate}
\begin{equation*}
     \up^{n+1} = \overline{\u} + \alpha (\tilde{\up} + \delta \u - \overline{\u}) \\
     \Leftrightarrow
     \up^{n+1} = \overline{\u} + \left(\tilde{\up} - \dfrac{\sum_p \Np \mp \tilde{\up}}{\sum \Np \mp} \right)\sqrt{\dfrac{\sum_p \Np \mp (\up^n - \overline{\u})^2}{\sum_p \Np \mp \left( \tilde{\up} - \dfrac{\sum_p \Np \mp \tilde{\up}}{\sum_p \Np \mp}\right)}}.
\end{equation*}

template<class ParcelType>
template<class TrackCloudType>
inline void Foam::MPPICParcel<ParcelType>::trackingData::updateAverages
(
    const TrackCloudType& cloud
)
{
    // zero the sums
    volumeAverage_() = 0;
    radiusAverage_() = 0;
    rhoAverage_() = 0;
    uAverage_() = Zero;
    uSqrAverage_() = 0;
    frequencyAverage_() = 0;
    massAverage_() = 0;

    // temporary weights
    autoPtr<AveragingMethod<scalar>> weightAveragePtr
    (
        AveragingMethod<scalar>::New
        (
            IOobject
            (
                IOobject::scopedName(cloud.name(), "weightAverage"),
                cloud.db().time().timeName(),
                cloud.mesh()
            ),
            cloud.solution().dict(),
            cloud.mesh()
        )
    );
    AveragingMethod<scalar>& weightAverage = weightAveragePtr();

    // averaging sums
    for (const typename TrackCloudType::parcelType& p : cloud)
    {
        const tetIndices tetIs = p.currentTetIndices();

        const scalar m = p.nParticle()*p.mass();

        volumeAverage_->add(p.coordinates(), tetIs, p.nParticle()*p.volume());
        rhoAverage_->add(p.coordinates(), tetIs, m*p.rho());
        uAverage_->add(p.coordinates(), tetIs, m*p.U());
        massAverage_->add(p.coordinates(), tetIs, m);
    }
    volumeAverage_->average();
    massAverage_->average();
    rhoAverage_->average(*massAverage_);
    uAverage_->average(*massAverage_);

        // squared velocity deviation
    for (const typename TrackCloudType::parcelType& p : cloud)
    {
        const tetIndices tetIs = p.currentTetIndices();

        const vector u = uAverage_->interpolate(p.coordinates(), tetIs);

        uSqrAverage_->add
        (
            p.coordinates(),
            tetIs,
            p.nParticle()*p.mass()*magSqr(p.U() - u)
        );
    }
    uSqrAverage_->average(*massAverage_);

    // sauter mean radius
    radiusAverage_() = volumeAverage_();
    weightAverage = 0;
    for (const typename TrackCloudType::parcelType& p : cloud)
    {
        const tetIndices tetIs = p.currentTetIndices();

        weightAverage.add
        (
            p.coordinates(),
            tetIs,
            p.nParticle()*pow(p.volume(), 2.0/3.0)
        );
    }
    weightAverage.average();
    radiusAverage_->average(weightAverage);

    // collision frequency
    weightAverage = 0;
    for (const typename TrackCloudType::parcelType& p : cloud)
    {
        const tetIndices tetIs = p.currentTetIndices();

        const scalar a = volumeAverage_->interpolate(p.coordinates(), tetIs);
        const scalar r = radiusAverage_->interpolate(p.coordinates(), tetIs);
        const vector u = uAverage_->interpolate(p.coordinates(), tetIs);

        const scalar f = 0.75*a/pow3(r)*sqr(0.5*p.d() + r)*mag(p.U() - u);

        frequencyAverage_->add(p.coordinates(), tetIs, p.nParticle()*f*f);

        weightAverage.add(p.coordinates(), tetIs, p.nParticle()*f);
    }
    frequencyAverage_->average(weightAverage);
}

From the new particle positions we can update the particle volume fraction and subsequently the fluid volume fraction
\begin{equation}
\label{eq:maxAlpha}
    \fvf = \max (1-\pvf,\fvf_{min})
\end{equation}
with $\fvf_{min}$ as a user defined input. This is used to prevent overpacking in cells that could lead to numerical instabilities.
The properties of the \lstinline|kinematicCloud| like the fluid volume fraction previously calculated are now interpolated to the Eulerian mesh.
In \lstinline|system/fvSchemes| the interpolation scheme is defined as linear. 
The interpolation used by \OF is the barycentric interpolation.
For the interpolation the cells are divided into eight tetrahedrons using the cell center and three vertices which we will call $\abar = (\abar_1, \abar_2, \abar_3),\bbar = (\bbar_1, \bbar_2, \bbar_3),\cbar = (\cbar_1, \cbar_2, \cbar_3),\dbar = (\dbar_1, \dbar_2, \dbar_3)$, given in global coordinates.\hfill

An  arbitrary point $p$ inside the tetrahedron can be represented using the four vertices and barycentric coordinates $\bwea, \bweb, \bwec, \bwed \in \mathbb{R}$, sometimes called weights
\begin{equation*}
    \pbar = \bwea \abar + \bweb \bbar + \bwec \cbar + \bwed \dbar
\end{equation*}
which must fulfill the following properties
\begin{align*}
    0 \leq \bwea, \bweb, \bwec, \bwed \leq 1  \qquad &\forall \pbar \in tetrahedron \\
    \bwea + \bweb + \bwec + \bwed = 1 \qquad &\forall \pbar.
\end{align*}
The second property is necessary to have a unique weight combination for each point.
The weights are proportional to the sub-tetrahedrons that are formed using $\pbar$, see figure \ref{fig:tetSub}.
%\Todo{Draw a picture}
The volume of a tetrahedron is a sixth of the corresponding parallelepiped with the lengths given by the edge length of the tetrahedron
\begin{equation*}
    V_{\abar, \bbar, \cbar, \dbar} = \dfrac{1}{6}\operatorname{det} \begin{pmatrix}
        \abar_1 & \abar_2 & \abar_3 & 1 \\
        \bbar_1 & \bbar_2 & \bbar_3 & 1 \\
        \cbar_1 & \cbar_2 & \cbar_3 & 1 \\
        \dbar_1 & \dbar_2 & \dbar_3 & 1        
    \end{pmatrix} = \operatorname{det} \begin{pmatrix}
        \abar_1 - \dbar_1& \abar_2 - \dbar_2& \abar_3 - \dbar_3& 0 \\
        \bbar_1 - \dbar_1& \bbar_2 - \dbar_2& \bbar_3 - \dbar_3& 0 \\
        \cbar_1 - \dbar_1& \cbar_2 - \dbar_2& \cbar_3 - \dbar_3& 0 \\
        \dbar_1 & \dbar_2 & \dbar_3 & 1  
    \end{pmatrix}= \operatorname{det} \begin{pmatrix}
     \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \bbar} & \overrightarrow{\dbar \cbar}   
    \end{pmatrix}
\end{equation*}
The barycentric coordinates are then given by
\begin{align*}
    \bwea &= \dfrac{V_{\pbar, \bbar, \cbar, \dbar}}{V_{\abar, \bbar, \cbar, \dbar}} = \dfrac{\begin{pmatrix}
     \overrightarrow{\dbar \pbar} & \overrightarrow{\dbar \bbar} & \overrightarrow{\dbar \cbar}   
    \end{pmatrix}}{\begin{pmatrix}
    \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \bbar} & \overrightarrow{\dbar \cbar}      
    \end{pmatrix}} \qquad
    &\bweb = \dfrac{V_{\pbar, \abar, \cbar, \dbar}}{V_{\abar, \bbar, \cbar, \dbar}} = \dfrac{\begin{pmatrix}
     \overrightarrow{\dbar \pbar} & \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \cbar}   
    \end{pmatrix}}{\begin{pmatrix}
    \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \bbar} & \overrightarrow{\dbar \cbar}      
    \end{pmatrix}}\\
    \bwec &= \dfrac{V_{\pbar, \abar, \bbar, \dbar}}{V_{\abar, \bbar, \cbar, \dbar}}= \dfrac{\begin{pmatrix}
     \overrightarrow{\dbar \pbar} & \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \bbar}   
    \end{pmatrix}}{\begin{pmatrix}
    \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \bbar} & \overrightarrow{\dbar \cbar}      
    \end{pmatrix}} \qquad
    &\bwed = \dfrac{V_{\pbar, \abar, \bbar, \cbar}}{V_{\abar, \bbar, \cbar, \dbar}}= \dfrac{\begin{pmatrix}
     \overrightarrow{\cbar \pbar} & \overrightarrow{\cbar \abar} & \overrightarrow{\cbar \bbar}   
    \end{pmatrix}}{\begin{pmatrix}
    \overrightarrow{\dbar \abar} & \overrightarrow{\dbar \bbar} & \overrightarrow{\dbar \cbar}      
    \end{pmatrix}}
\end{align*}
with the last one simplifying to
\begin{equation}
\label{eq:baryNorm}
    \bwed = 1 - \bwea - \bweb - \bwec
\end{equation}
due to our properties.

We can use the following transformation to switch between our barycentric coordinate system and the global coordinates
\begin{equation*}
    \pbar = A \bwe (p) \Leftrightarrow \begin{pmatrix}
        x_p \\ y_p \\ z_p
    \end{pmatrix} =
    \begin{pmatrix}
        x_\abar & x_\bbar & x_\cbar & x_\dbar \\
        y_\abar & y_\bbar & x_\cbar & x_\dbar \\
        z_\abar & z_\bbar & z_\cbar & z_\dbar
    \end{pmatrix}
    \begin{pmatrix}
        \bwea \\ \bweb \\ \bwec \\ \bwed
    \end{pmatrix}
    \Leftrightarrow
    \begin{pmatrix}
        x_p \\ y_p \\ z_p
    \end{pmatrix} =
    \begin{pmatrix}
        x_\abar - x_\dbar & x_\bbar- x_\dbar & x_\cbar- x_\dbar \\
        y_\abar- y_\dbar & y_\bbar - y_\dbar& x_\cbar- y_\dbar \\
        z_\abar - z_\dbar & z_\bbar - z_\dbar & z_\cbar - z_\dbar
    \end{pmatrix} \begin{pmatrix}
         \bweb \\ \bwec \\ \bwed
    \end{pmatrix}
\end{equation*}
where we used \eqref{eq:baryNorm} in the last step.
Therefor transforming between our global coordinates and our local barycentric coordinates can be done by inverting a $3 \times 3$ matrix.


The barycentric coordinates are used as weights to interpolate Eulerian filed properties to the parcels
\begin{equation}

Analogy particle properties are interpolated to vertices.
If particles move through several tetrahedra during the \lstinline|motion| they are moved to the face and the id is given to the following tetrahedron. The particle is then tracked in the next tetrahedron.

We start with the momentum equation which is solved for $\uf$
\begin{equation}
\begin{aligned}
\label{eq:momentumOF}
    \color{kit-blue}
    \underbrace{\dfrac{\partial}{\partial \tvar} (\fvf  \uf )}_{\texttt{fvm::ddt(alphac, Uc)}} & \color{kit-blue}+ \underbrace{\nabla \cdot (\fvf \uf \uf)}_{\texttt{fvm::div(alphaPhic, Uc)}} - \underbrace{\uf \left( \dfrac{\partial \fvf}{\partial \tvar} + \nabla \cdot (\fvf \uf) \right)}_{\substack{\texttt{fvm::Sp(fvc::ddt(alphac)} \\ + \texttt{fvc::div(alphaPhic), Uc)}}} - \underbrace{\nabla \cdot (\fvf \ss_c)}_{\substack{\texttt{continuousPhaseTurbulence} \\ \texttt{->divDevRhoReff(Uc)}}} \\ 
    & = \color{kit-green}

\end{aligned}

The equation is relaxed to ensure diagonal-dominance needed for convergence. This is discretized as
\begin{align*}
    A_P \ufc + \sum_N A_N \ufn - S_p = - \dfrac{S_{transfer}}{\rf}

    volVectorField HbyA(constrainHbyA(rAUc*UcEqn.H(), Uc, p));

    surfaceScalarField phiHbyA
    (
        "phiHbyA",
        (
           fvc::flux(HbyA)

        )

    if (p.needReference())
    {
        adjustPhi(phiHbyA, Uc, p);
    }

    phiHbyA += phicForces;

    // Update the pressure BCs to ensure flux consistency
    constrainPressure(p, Uc, phiHbyA, rAUcf);

    // Non-orthogonal pressure corrector loop
    while (pimple.correctNonOrthogonal())
    {
        fvScalarMatrix pEqn
        (
            fvm::laplacian(alphacf*rAUcf, p)
         ==
            fvc::ddt(alphac) + fvc::div(alphacf*phiHbyA)
        );

        pEqn.setReference(pRefCell, pRefValue);

        pEqn.solve(p.select(pimple.finalInnerIter()));

        if (pimple.finalNonOrthogonalIter())
        {
            phic = phiHbyA - pEqn.flux()/alphacf;

            p.relax();

            Uc = HbyA
              + rAUc*fvc::reconstruct((phicForces - pEqn.flux()/alphacf)/rAUcf);
            Uc.correctBoundaryConditions();
        }
    }
